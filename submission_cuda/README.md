# Assignment 2 — CUDA notebook workflow

The three self-contained notebooks are generated by `build_cuda_submission.py`:

1. `Breakout_DQN_PPO_CUDA.ipynb` — DQN and revised PPO, custom CNN, random baseline, periodic fixed-seed evaluation, final comparison and two MP4s.
2. `CartPole_DQN_PPO_CUDA.ipynb` — DQN and PPO, custom ANN, independent episode counts, comparison and two MP4s.
3. `Pendulum_Q_Learning.ipynb` — existing validated Q-Learning experiment, with one MP4.

Run each from top to bottom in the NVIDIA CUDA Python kernel. Open the project directory as the notebook working directory. Install `requirements-cuda.txt` into the existing CUDA environment **without replacing its working CUDA PyTorch build**. The notebooks print the active Python executable and GPU at the beginning. Save each notebook after execution so outputs appear in the submitted `.ipynb`.

The Breakout revision is an experiment, not a guaranteed improvement. Compared with the prior PPO run, it uses a 2,048-step rollout instead of 128, batch size 256, a decaying learning rate, evaluation every 200,000 steps on ten fixed seeds, and saves the best model only after one million training steps. DQN and PPO use the same 30 fixed seeds for final raw-reward evaluation. New artifacts go under `submission_cuda_outputs/` and never inherit the old interleaved Monitor logs. Training graphs show clipped training reward; evaluation graphs show unclipped environment reward.

The Breakout DQN target is 3.6 million time steps and the PPO target is 6 million. CartPole targets 10,000 completed episodes per algorithm. These are code targets, **not completed results** until the CUDA notebooks have been run. For Breakout DQN resumption, keep the replay buffer as well as the model checkpoint. Do not copy historical ZIP results into the new report. Evaluate and record videos from the new saved models; use the generated CSV values in the report.

The Pendulum notebook is copied from the existing `Pendulum_TD_Q_Learning.ipynb` without changing its historical results. If you rerun it, save its new outputs and align the report with that run. Its output folder is `pendulum_artifacts/` rather than `submission_cuda_outputs/`.

The MP4s, saved models, logs and CSVs are ignored by Git; transfer them separately to the submission location. Check the course submission rules and AI declaration before final packaging.
